# Т-Банк MCP: автообновление и восстановление сессии

Обновлено 17.11.2026. Вход через Android и перенос на Windows проверены
16.11.2026 для клиента 0.3.2. Скрипты восстановления добавлены в commit
`8d50838121692fd185e1d994ff70a9649f3e979d`; совместимая версия с исправлением
OAuth consent — `c24041eeb5724abf18e810374200506a0ba309b4`.

## Карта восстановления без истории чата

- Код клиента, вход на телефоне и шифрование: этот репозиторий.
- Инфраструктура VPS: отдельный `hermes-customizations`, manifest
  `components/tbank-mcp.json`, инструкция `docs/TBANK_SESSION_RENEWAL.md`.
- `tbank-session.enc` — результат команды `export`, зашифрованный отдельным
  паролем владельца. Для расшифровки нужны и файл, и этот пароль; восстановить
  пароль из Git, Infisical или ZIP плагина нельзя. При утрате пароля нужен новый
  вход на телефоне и новый экспорт. Имя с суффиксом даты тоже допустимо.
- Актуальное состояние банка — обновляемый JSON на единственном рабочем VPS.
  Первоначальный `.enc` после ротации может устареть. Хранить секретные файлы
  вне checkout и OneDrive; не прикладывать их к issues и сообщениям агента.
- Экспорт ZIP плагина ChatGPT находится в инфраструктурном репозитории в
  `exports/chatgpt-plugins/`; он не содержит банковских токенов. При потере
  подключения восстанавливается отдельно от банковской сессии.

## Как работает обновление

- Перед чтением клиент проверяет возраст токена и при необходимости выполняет
  обмен `refresh_token`. Фоновый таймер для этого в клиенте не предусмотрен.
- Новые токены должны записываться в тот же `TBANK_SESSION`. У read-only клиента
  автоматический refresh разрешён; `silent_relogin` отключён.
- Периодический вход через Termux по расписанию не требуется. Если банк отзовёт
  refresh-токен или потребует подтверждение, понадобится новый интерактивный вход.
- Фиксированный срок жизни refresh-токена и бессрочная работа не гарантированы.
- Банковская сессия и OAuth-подключение ChatGPT — разные уровни авторизации.
  Замена банковской сессии обычно не требует пересоздания плагина, если issuer,
  OAuth-БД и ключ её шифрования сохранены.

## Требования к VPS и деплоям

Пути ниже предусмотрены существующей документацией проекта. До выполнения
операций сверить их с unit и manifest в `hermes-customizations`.

| Данные | Место |
|---|---|
| Обновляемая банковская сессия | `/var/lib/tbank-readonly/session.json` |
| OAuth-БД | `/var/lib/tbank-readonly/oauth.sqlite` |
| CA bundle | `/var/lib/tbank-readonly/bundle.pem` |
| Статические секреты | Infisical, штатный renderer в `/run/hermes-secrets/tbank.env` |
| Процесс | `hermes-tbank-mcp-http.service` |

1. Каталог состояния находится вне checkout, venv и сменяемых релизов. Для
   контейнера нужен постоянный том, а не слой образа или эфемерный каталог.
2. Сервисный пользователь должен иметь право записи в каталог сессии: сохранение
   использует временный файл и переименование. Одного права записи в JSON мало.
3. Закрытые права: каталог состояния `0700`, сессия `0600`, владелец — пользователь
   службы. Учитывать также `ReadWritePaths` и другие ограничения systemd.
4. Деплой не копирует первоначальную сессию поверх текущей, не восстанавливает её
   автоматически из старого архива и не выполняет bootstrap при наличии файла.
5. Сохранять OAuth-БД и `TBANK_MCP_STATE_KEY`; ключ не генерировать заново при
   перезапуске. Резервную копию SQLite делать согласованным способом, учитывая WAL.
6. На одну банковскую сессию работает один процесс/worker. Исключить параллельный
   запуск на ПК, телефоне, другом VPS и перекрытие старого/нового процесса при
   rolling/blue-green деплое. Процессный `_MINT_LOCK` не защищает между процессами.
7. Защищённые резервные копии нужны, но старый refresh-токен после ротации может
   быть недействителен: backup не гарантирует восстановления доступа к банку.
8. `TBANK_TRACE=0`. Проверять сохранение сессии после реальной ротации и чтение
   после штатного перезапуска; не считать один успешный запрос доказательством
   долговременного хранения. Содержимое токенов в логи не выводить.

В Infisical хранятся `TBANK_MCP_OWNER_PASSWORD` (отдельный код подключения MCP)
и `TBANK_MCP_STATE_KEY`. Пароль банка, PIN и SMS туда не заносятся.
`session.json` и OAuth-БД — изменяемое закрытое состояние сервиса.
`tbank-session.enc` — зашифрованный пакет переноса, а не постоянный источник
сессии для деплоя. После ротации он может устареть.

## Если подключение перестало работать

1. Сначала различить сетевой/TLS-сбой, ошибку OAuth ChatGPT и отказ банковского
   refresh. Не начинать новый вход только из-за timeout или HTTP 401 на публичном
   MCP без OAuth-токена — последний ответ ожидаем.
2. Проверить, нет ли второго процесса, сбоя записи файла или восстановления старого
   JSON. При `invalid_grant`, `SESSION EXPIRED` или требовании повторного входа
   после проверки причин переходить к восстановлению ниже.
3. Не устраивать циклическую отправку SMS. Если код не приходит, выдержать около
   30 минут после предыдущего запроса; это рекомендация автора issue №3, а не
   гарантированный срок снятия ограничений банка.

## Подготовка Termux

Установить Termux из F-Droid. В Termux выполнить:

```bash
pkg update && pkg upgrade -y
pkg install -y python python-pip git python-cryptography
termux-setup-storage
cd ~
git clone https://github.com/sidrez/tbank-mcp.git
cd ~/tbank-mcp
python -m venv --system-site-packages .venv
.venv/bin/python -m pip install requests
```

Если checkout уже существует, повторно клонировать его не нужно. Скрипты
`bin/tbank_termux_login.py` и `bin/tbank_session_transfer.py` должны присутствовать
в checkout. Если их нет в старом закреплённом commit, сначала сохранить свои
изменения и перейти на согласованный актуальный commit репозитория. Не выполнять
`reset --hard` и не менять версию действующего VPS ради обновления телефона.

Полный MCP и Playwright на телефоне для входа не требуются.
При запросе Android разрешить Termux доступ к файлам для зашифрованного экспорта
в «Загрузки». Termius не заменяет Termux и этих команд не предоставляет.
Копировать `.enc` можно из Android «Мои файлы → Загрузки»; исходный JSON из
внутреннего `$HOME` Termux в общее хранилище копировать не нужно.

## Повторный вход через Android Termux

Перед входом остановить банковский MCP на VPS и прекратить локальные обращения.
Остановку и замену runtime state выполнять в согласованном окне обслуживания.
Для штатной службы команда:

```bash
sudo systemctl stop hermes-tbank-mcp-http.service
```

На телефоне отключить VPN, использовать мобильный интернет. В Termux выполнить:

```bash
cd ~/tbank-mcp
renewal_tag=$(date +%Y%m%d-%H%M%S)
new_session="$HOME/.local/share/tbank-mcp/session-$renewal_tag.json"
.venv/bin/python bin/tbank_termux_login.py --output "$new_session"
```

Ввести телефон, код и только запрошенные банком пароль/PIN. Ввод скрытый.
Используется новое имя: скрипт намеренно отказывается перезаписывать имеющуюся
сессию. **Только после сообщения «Сессия сохранена»** выполнить:

```bash
.venv/bin/python bin/tbank_session_transfer.py export \
  --input "$new_session" \
  --output "$HOME/storage/downloads/tbank-session-$renewal_tag.enc"
```

Задать отдельный пароль переноса минимум 12 символов, повторить его. Передать
полученный `.enc` на ПК. Незашифрованный JSON на общедоступное хранилище Android
не копировать. Пароль и файл банковской сессии в чат не отправлять.

## Импорт на ПК и замена на VPS

Открыть локальный PowerShell в корне checkout `tbank-mcp` и ввести команды ниже. В первой строке указать фактический
путь к новому `.enc`, а не первоначальному архиву переноса.

```powershell
$encryptedPath = Read-Host 'Полный путь к новому .enc'
$privateDir = Join-Path $env:LOCALAPPDATA 'tbank-mcp'
New-Item -ItemType Directory -Path $privateDir -Force | Out-Null
$userSid = [System.Security.Principal.WindowsIdentity]::GetCurrent().User.Value
icacls.exe $privateDir /inheritance:r /grant:r ('*' + $userSid + ':(OI)(CI)F')
if ($LASTEXITCODE -ne 0) { throw 'Не удалось ограничить доступ к каталогу' }
$renewalDir = Join-Path $env:LOCALAPPDATA ('tbank-mcp\renewals\' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
$repoPath = (Get-Location).Path # PowerShell открыт в корне checkout tbank-mcp
$pythonPath = Join-Path $repoPath '.venv\Scripts\python.exe'
$transferScript = Join-Path $repoPath 'bin\tbank_session_transfer.py'
& $pythonPath $transferScript import --input $encryptedPath.Trim('"') --output (Join-Path $renewalDir 'session.json')
```

Пароль вводится в локальном терминале. Перед импортом закрыть каталог `%LOCALAPPDATA%\tbank-mcp` NTFS ACL для
владельца. Если защита уже настроена, проверить её сохранение. Без этого
`0600` из Python не гарантирует ограничение доступа в Windows.
Не заменять ещё работающую сессию без остановки её единственного потребителя.

Далее выполнить операции штатным SSH/SCP-подключением к домену по инструкции
`hermes-customizations/docs/TBANK_SESSION_RENEWAL.md`. Там также описан вариант
импорта `.enc` непосредственно на VPS без расшифровки на ПК.

1. Проверить остановку службы и отсутствие второго потребителя сессии.
2. Передать новый JSON по SSH в закрытый staging-каталог на VPS. Не печатать файл.
3. Проверить JSON и обязательные поля без вывода их значений. Сохранить защищённый
   backup прежнего состояния; убедиться, что backup не попадает в Git/артефакты.
4. Подготовить новый файл в каталоге состояния, выставить владельца службы и
   `0600`, затем атомарно заменить `/var/lib/tbank-readonly/session.json`.
5. OAuth-БД, ключ шифрования и URL issuer не менять. Запустить службу:

   ```bash
   sudo systemctl start hermes-tbank-mcp-http.service
   sudo systemctl is-active hermes-tbank-mcp-http.service
   ```

6. Проверить через авторизованный MCP `session_status` и `list_accounts`, наличие
   ровно 17 разрешённых read-only tools и HTTP 401 без OAuth. Затем проверить
   реальный вызов из ChatGPT. Не выводить банковские идентификаторы и токены в лог.
7. При неудаче сохранить точную обезличенную ошибку. Откат файла не гарантирует
   рабочий refresh-токен; не зацикливать перезапуски и повторный вход.
8. Убедившись в работе VPS, не использовать новые и старые копии сессии на ПК и
   телефоне. Очистку ненужных секретных копий выполнить отдельно с разрешения
   владельца; остановка использования не равнозначна удалению.

## Что уже проверено

Полный вход через Termux и перенос на Windows выполнены успешно. На Windows
работают 17 read-only tools, статус сессии, чтение 4 счетов и истории операций.
Ротация токенов и их сохранение после перезапуска на VPS в исходном чате ещё
не подтверждались — это отдельный обязательный этап проверки развёртывания.
