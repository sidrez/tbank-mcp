# Переводы между своими рублёвыми счетами

Функция включается отдельно от чтения: `TBANK_ENABLE_OWN_TRANSFERS=1` только
для `tbank-mcp-http`. Обычный stdio MCP остаётся с 17 инструментами чтения.
Для Hermes используется stdio-мост к этому же HTTP-процессу, а не второй
процесс с банковской сессией. Всего в HTTP-режиме 20 инструментов.

## Подтверждение внутри ChatGPT и Hermes

1. `list_accounts` находит актуальные счета. При неоднозначном названии агент
   уточняет выбор. Разрешены разные собственные Current/Saving с валютой RUB.
   Кредитные, валютные, чужие и инвестиционные счета исключены.
2. `prepare_own_transfer` принимает ID двух счетов и сумму строкой, например
   `10.25`. Проверяет остаток и комиссию через банк, сохраняет неизменяемый
   план на 10 минут. Деньги ещё не отправляются.
3. `confirm_own_transfer` получает только `transfer_id`. Сервер показывает
   штатный диалог клиента: сумма, названия счетов, последние 4 цифры и комиссия.
   Только ответ Accept от клиента разрешает повторную проверку и один POST.
   Параметра `confirmed=true` нет. Страница вне ChatGPT/Hermes не нужна.
4. `own_transfer_status` показывает сохранённый исход; он не отправляет платёж.

Поддерживается стандартное MCP form elicitation и legacy-расширение OpenAI
`openai/elicitation/create` для прямого подключения. Если клиент не объявил
совместимую capability, отменил диалог или вернул ошибку — перевод запрещён.
Появление конкретного диалога зависит от клиента, версии и способа подключения;
без поддержки нет текстового обхода. Секреты банка через диалог не запрашиваются.

OAuth-разрешения: `bank:read` для чтения, отдельно `bank:transfer-own` для
исполнения. Старые токены чтения не повышаются автоматически. Если приложение
при переподключении по-прежнему запрашивает только чтение, создать новое
пользовательское подключение с обоими scopes. Одно обновление инструментов
не меняет сохранённые OAuth scopes приложения. На OAuth-странице должно быть
явно написано про собственные переводы.

### Ограничения клиентов ChatGPT

По [спецификации OpenAI](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md#platform-support)
на 25.11.2026 расширенные формы не поддерживаются в ChatGPT для Android и iOS.
Если клиент не объявил поддержку формы, чтение и подготовка доступны, а
подтверждение возвращает `not_sent`. Это ограничение MCP-клиента, не отказ банка
и не причина повторять вход в Termux или заменять банковскую сессию.

Для OpenAI-registered подключений та же спецификация требует MCP 2026-07-28
и MRTR; текущий сервер на MCP SDK 1.x поддерживает только описанный выше legacy
вариант прямого подключения. Поддержку подтверждения в браузере или настольном
клиенте нужно проверять отдельно: наличие 20 инструментов и успешная подготовка
не доказывают появление формы. Проверка — увидеть сумму и оба счёта в штатном
диалоге и выбрать отмену. Кнопка разрешения вызова инструмента сама по себе
не является подтверждением перевода. Текстового обхода проверки нет.

## Состояние и ограничения

- Комиссия строго 0, итоговая сумма должна совпадать. Лимит по умолчанию
  100 000 RUB; меняется владельцем через `TBANK_OWN_TRANSFER_MAX_RUB` на сервере.
- API неофициальный. Контракт `payment_commission`/`pay` восстановлен по
  локальной записи браузера от 25.11.2026. Сырые HAR, cookie и fingerprint
  пользователя не входят в код. Проверка комиссии с VPS вернула OK;
  это не является проверкой исполнения реального перевода.
- Платёж не повторяется после сетевой ошибки, ответа с дополнительным
  банковским подтверждением или падения процесса. `unknown`, `posting`,
  `checking`, `bank_confirmation` требуют ручной сверки операций в банке.
  Для такой же пары счетов и суммы новый план блокируется.
- `confirmed` означает OK и paymentId от банка. Повтор подтверждения того же
  плана не отправляет платёж. Повтор подготовки в течение 10 минут возвращает
  тот же план, в том числе при уже известном успехе.
- `own-transfers.sqlite` хранится рядом с OAuth-БД; реквизиты и банковские ID
  зашифрованы тем же постоянным `TBANK_MCP_STATE_KEY`. Не удалять журнал для
  разблокировки и не восстанавливать старую БД поверх текущей после платежа.

## VPS и Hermes

Дополнительно к обычным переменным HTTP-сервиса:

```ini
TBANK_ENABLE_OWN_TRANSFERS=1
TBANK_MCP_HERMES_TOKEN_FILE=/var/lib/tbank-readonly/hermes-token
TBANK_OWN_TRANSFER_MAX_RUB=100000
```

HTTP-процесс создаёт закрытый token-файл 0600; его значение не попадает в Git,
конфиг агента или чат. Hermes запускает:

```yaml
mcp_servers:
  tbank:
    command: /opt/tbank-mcp/venv/bin/python
    args: [-m, tbank_mcp.hermes_bridge]
    enabled: true
    lazy: true
    supports_parallel_tool_calls: false
    connect_timeout: 20
    timeout: 180
    env:
      TBANK_MCP_HERMES_TOKEN_FILE: /var/lib/tbank-readonly/hermes-token
```

Мост передаёт диалог обратно в Hermes и ждёт действия пользователя. Он не
загружает и не обновляет банковскую сессию. nginx должен сохранять HTTP/SSE
соединение (buffering off, read timeout не меньше времени подтверждения).
При включении переводов HTTP использует stateful Streamable HTTP для обратных
запросов; после перезапуска клиент устанавливает новое MCP-соединение.

Если Hermes сообщает, что MCP не подключён, сначала выполнить на VPS
`hermes mcp test tbank`: ожидаются подключение и 20 инструментов. Даже при
здоровом MCP старая беседа может хранить прежний набор инструментов. В той же
беседе Telegram выполнить `/reload-mcp`, затем попросить проверить
`session_status` и `list_accounts` без перевода; альтернатива — новая беседа.
Телефон для работы MCP на VPS не требуется. Ошибка поиска инструмента и
недействительная банковская сессия — разные неисправности: повторный вход через
Termux нужен только при подтверждённом отказе банковской авторизации.

В управляемом окружении изменения unit/config/component pin выполняются только
через репозиторий `hermes-customizations` и deployment engine с backup.
Банковская сессия, OAuth-БД, журнал планов и token-файл остаются вне release.

При слетевшем входе используйте [инструкцию Termux и восстановления сессии](SESSION_RENEWAL_RU.md).
При восстановлении меняют только банковскую сессию с остановленным сервисом;
журнал переводов, OAuth-БД и ключ шифрования сохраняют. На старте не запускается
ни один подготовленный или неопределённый платёж. Для возврата к чтению
отключают `TBANK_ENABLE_OWN_TRANSFERS`, сохраняя весь runtime-state.

## Проверки без реальных денег

```bash
python tests/test_own_transfers.py
python tests/test_transfer_transport.py
python tests/test_readonly.py
python tests/test_http_oauth.py
```

Тесты используют синтетический банк; проверяют ограничение счетов, комиссию,
истечение плана, конкурирующие подтверждения, неизвестный исход, OAuth scopes,
подпись запроса, HTTP/SSE и передачу отмены через stdio-мост Hermes.
